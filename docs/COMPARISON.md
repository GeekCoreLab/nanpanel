# 竞品功能对照（自检）

对照 KubeSphere、1Panel、宝塔面板，逐项标注 **NaNPanel 做到哪一步**。目的有两个：让后续开发不靠记忆；
对使用者诚实说明边界，不把「代码写完」说成「功能可用」。

**状态含义**

| 标记 | 含义 |
| --- | --- |
| ✅ | 已实现，且有**离线自动化测试**覆盖（契约/语义/边界） |
| 🟡 | 已实现，但**端到端验收需要真机或真实集群**（本仓库的测试只到契约层） |
| ⛔ | 未实现 |

自动化测试基线（最近一次全绿）：Rust **95** · Java **204**（Core 176，2 项 LiveTest 离线跳过）· Web **98**。验收流程见 `docs/testing/README.md`。

## 三、平台与安全（自组织面板的底座）

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 会话认证、强制改密、密码策略 | ✅ | 会话轮换 + CSRF + 最近认证（re-auth）门禁 |
| 角色与权限 | ✅ | 36 项权限词表；`EndpointPermissions` 反射式覆盖测试保证「新端点必须映射权限」 |
| 账号角色分配 / 自定义角色 | ✅ | 内置 ADMIN 不可改不可删；在用角色不可删；角色**真的**决定接口可达性 |
| 审计日志 | ✅ | 关键写操作全部留痕，可按动作/结果筛选 |
| API 密钥 | ✅ | 独立作用域校验，不参与角色判定 |
| 操作任务中心 | ✅ | 按创建时间倒序、键集分页、能力/主机/状态筛选 |
| 配置导出 / 导入（含预演） | ✅ | 校验和 + 版本门禁；站点一律以草稿导入 |
| 主机/容器/站点/路由的安全边界 | ✅ | 非 root Agent + 受限 root Helper + mTLS + 审计；容器默认 `--read-only` + `--cap-drop=ALL` |

## 四、明确不做（避免功能膨胀）

- 不内置 Prometheus/Loki/ELK 等观测栈（应由集群侧提供，面板只读）。
- 不做 CI/CD 流水线（KubeSphere 的主场，且与「面板」定位冲突）。
- 不自建 API 网关：路由一律编译成既有的 Istio VirtualService / 受管 Nginx 路由。
- 不提供 FTP、邮件服务器等传统面板捆绑件。

## 五、验收待办（在真机/真集群上才算完成）

1. 一键装/升/卸应用商店条目（真实 Docker/Podman）。
2. 计划任务在真实主机上的 cron.d 加载与执行。
3. 站点下发、停用、TLS 证书握手（真实 Nginx + 域名）。
4. K3s 安装与滚动升级（真实空白主机）。
5. 拖拽路由 Apply/Verify/Compensate（真实 Istio + sidecar 注入的 Namespace）。
6. 堡垒机会话与录像（真实 SSH 目标）。
7. ACME 自动签发证书（需公网域名与 80 端口挑战）。

> 这些项的代码与契约测试已就绪，但本仓库的 CI 环境不具备真实主机/集群，因此一律记为 🟡 而非 ✅。
