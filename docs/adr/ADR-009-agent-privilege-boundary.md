# ADR-009：普通用户 Agent + root Helper

状态：接受（已实现）

## 背景

平台需承接系统管理职责，包括软件包、systemd、防火墙、路由、文件和系统级容器。Agent 必须能请求 root 操作，但网络通信和所有任务逻辑不应持有 root 权限。

## 决策

Agent 与自研边缘控制器使用专用普通用户；Rust `privileged-helper` 以 root 运行，通过 Unix Domain Socket 接收固定类型能力请求。两个 systemd unit 直接使用宿主机环境，不设置 systemd 文件系统、临时目录、内核或 syscall 沙箱。Helper 校验调用方身份、操作类型、目标和结构化参数，执行固定系统命令，记录脱敏审计并限制超时、输出和并发。Helper 不读取逐项操作名单，不接受任意命令文本。

Agent/Helper 协议不提供任意 Shell 执行接口。需要交互式远程终端时，作为独立的管理员高权限功能授权和审计，不借道 Agent 或 root Helper。主机 SSH 堡垒功能按 [ADR-012](ADR-012-host-ssh-bastion.md) 实现资产级 SSH 凭据、host key 确认、会话票据和终端录像。Agent 非 root 与容器 rootless 相互独立：系统可按工作负载管理 rootful 和 rootless 容器。

## 实施与验收

实际特权执行通过独立 Helper 落地。已验证授权调用成功、非可信调用方和越权参数被拒绝、网络变更可回退、结果有审计。Helper 的固定操作接口不需要主机管理员逐项配置名单。systemd、软件包、受保护文件、容器和网络操作按格式校验目标及参数；主机文件管理支持浏览绝对路径及读写/删除普通文件，拒绝 `.`、`..` 和符号链接，并对结果大小进行限制。容器资源约束和网络自动回滚继续生效。

## 代价

增加 IPC、协议版本和安装权限管理；换取更小的高权限代码范围。Helper 仍可能因实现缺陷危及宿主机，进程拆分本身不替代身份验证、固定操作接口与参数校验。
